# 分集剧本写作

## 这个 skill 用来做什么

把 brief / 改编策略 / 原文要点 / 续写指令落地为**可分集、可拆镜的纯文本剧本正文**。  
本 skill 只写叙事层（场次头、动作、对白），不写分镜、不写提示词、不写导演术语。

运行入口：`POST /agent/script/screenplay`（以及编剧台「生成 / 续写 / 重写」复用该入口）。  
**输出必须是纯文本剧本，禁止 JSON、禁止解释性前言/后记。**

## 输入要求

用户消息可能包含以下任意组合，按优先级吸收：

1. 标题 / logline / 大纲 / 人物 bible
2. 目标集数或「请写第 N 集」
3. 已有集正文（续写 / 重写时的上下文与格式样例）
4. 用户补充要求（语气、反转、禁区等）

生成前必须确认 `bible.world.visualStyleNotes` 已选择明确的全片视觉风格（真人写实、写实 3D、风格化 3D、二维动漫、国漫水墨、定格动画等）。未选择时不得写剧本；一旦选择，所有人物和场景描写必须服从该风格，禁止生成中途切换视觉形态。

若信息不足：在合理范围内补全短剧可拍场面，但**不得**无依据新增主线大事件或更换主角姓名。

## 输出要求

### A. 容器格式（硬性）

- **只输出纯文本剧本**。不要 markdown 代码围栏，不要 JSON，不要「好的，下面是剧本」之类说明。
- 多集时：每一集必须以独立标题行开头，集与集之间空一行：
  - `第1集 标题`
  - `第2集 标题`
- 单集（续写/重写）时：同样以 `第N集 标题` 开头，且**只写这一集**，不得复述其他集。
- `title` 语义落在标题行：`第N集` 后空一格接短标题（≤20 字），不要把整段剧情塞进标题。

### B. body 体例（全系列锁死，不可混用）

每集正文**只能**由三类行组成，顺序固定为：场景头 → 动作 → 对白（可循环多场）。

#### 1) 场景头（唯一合法形态）

```text
## S01 | 内景 · 咖啡厅 | 白天
## S02 | 外景 · 青水路 | 傍晚
## S03 | 内景 · 出租屋 | 深夜
```

规则：

- 必须以 `## S` + 两位数字场号开头（本集内从 `S01` 起连续编号）。
- 三段用 ` | ` 分隔：`内景/外景 · 地点 | 时间`。
- 地点用具体可拍场所（咖啡厅、出租屋、茶楼雅间），禁止空泛「某处」。
- 时间只用：`白天` / `傍晚` / `夜晚` / `深夜` / `清晨`（可加「雨夜」等短修饰，但不要写时钟）。
- **禁止**以下变体（全部视为失败）：
  - `咖啡厅。白天。`
  - `【场景：咖啡厅，白天】` / `【场景】…`
  - `场景一：…` / `INT.` / `EXT.`
  - 无 `## Sxx` 的自由场景说明

#### 2) 动作行

- 自然段叙述，写**可见可拍**的外部动作、表情、空间关系、物件互动。
- 一段一事，短句优先；避免散文抒情与大段心理独白。
- 必要的内心可用一句极短旁白，但推动情节必须靠动作/对白。
- **禁止**镜头语言：特写、中景、推拉摇移、镜头、cut、OS、VO 技术标注、分镜表、imagePrompt。

#### 3) 对白行（唯一合法形态）

```text
李稳：红姨，我到了！
红姨（电话）：怎么不靠谱？
苏曼（冷）：你叫我什么？
刀疤：少废话！要么谈钱，要么谈命！
```

规则：

- 格式：`角色名：台词` 或 `角色名（状态/方式）：台词`
- 角色名与 bible / 前文**同名唯一**；临时路人可用「司机」「店员」等职能名，但同一人全集不得改名。
- **禁止**给台词加中英文引号：`司机："上来"`、`李稳：「……」` 均失败。
- **禁止**小说式「李稳说道：」；必须独立成行的剧本对白。
- 电话/画外可用 `（电话）` / `（画外）`，不要写 `OS`/`VO`。

### C. 正例（必须对齐此体例）

```text
第1集 人生规划表

## S01 | 内景 · 咖啡厅 | 白天

李稳坐在靠窗卡座，衬衫洗得发白，桌上放着一杯柠檬水和一张叠整齐的A4纸，纸上写着「人生规划表」。手机响，他赶紧接起来。

李稳：红姨，我到了！你说的那个姑娘……靠谱吗？
红姨（电话）：怎么不靠谱？人家自己开公司的。稳儿，人生规划表带了没？
李稳：带着呢。五年计划、三年目标、每月储蓄，都列好了。

门被推开。两个黑西装先进来扫场，随即让开。一个女人走进来：黑长外套，墨镜，红唇，气场压得全场静了两秒。她在李稳对面坐下。

李稳：请问……您是不是坐错了？
苏曼（摘墨镜）：李稳？红姨介绍的？
```

### D. 负例（出现任一即失败）

- 输出 JSON：`{"episodes":[...]}` 或 `{"patch":...}`
- 混用 `【场景：…】` 与 `## S01 | …`
- 对白带引号：`苏曼："坐下。"`
- 集末写 `（完）` / `全文完` / `END`（除非用户明确要求「大结局终章」且本集确为最终集）
- 夹带：`特写李稳的手`、`镜头推进`、`imagePrompt:`、景别表
- 续写时复述上一集全文，或一次输出多集（当指令只要一集时）
- 无场景头的纯小说连载正文

## 工作流程

1. **判定任务类型**
   - 首发生成多集：按用户集数写 `第1集`…`第N集`，每集体例一致。
   - 续写一集：只写目标集；开场必须承接上一集人物状态、地点余波、未解悬念。
   - 重写一集：只替换目标集；保留核心剧情功能；衔接上一集结尾，且不与下一集开头矛盾。
2. **锁定名册**：主角/重要配角姓名以 bible 与已有正文为准；别名须在对白里交代清楚（例如对外化名），正文说话人标签仍保持可追踪。
3. **锁定视觉风格**：将 `bible.world.visualStyleNotes` 视为全片硬约束，所有人物外观、动作可视化描述和场景质感不得与其冲突。
4. **拆场**：每集 2–5 场为宜（短剧）；场号 `S01` 起编；每场先场景头，再动作与对白。
5. **戏剧弧**：开场 3–8 行内给钩子；中段升级冲突；集末留可续写钩子（电话、上门、反转预告），禁止无故烂尾，也禁止误标完结。
6. **体例自检**：开写前若用户提供了「格式样例/上一集正文」，**必须逐项复制其体例**（场景头、对白冒号、无引号），不得换套写法。
7. **直接输出正文**：无前言后记。

## 约束与边界

### 格式锁（最高优先级）

- 全系列体例必须自洽；续写/重写时以上一集（或用户给出的格式样例）为准，**禁止**中途改用另一套场景头/对白标点。
- 若上一集体例本身不规范，续写仍输出**本 skill 规定的标准体例**（不要继承错误的 `【场景】` 或引号对白），但剧情必须衔接。

### 叙事锁

- 角色同名唯一；不得无依据杀死/替换主角，或引入与大纲矛盾的世界观崩坏。
- 不得把已发生事实改成没发生（除非用户明确要求改史）。
- 续写禁止重置人物关系；重写禁止写出与邻集矛盾的结局。

### 片种与篇幅（缺省按短剧）

| 情境 | 要求 |
|------|------|
| 短剧/快手抖音感 | 每集约 800–1800 字；强钩子；口语对白；反转清晰 |
| 用户指定集数 | 严格按集数输出；不多不少 |
| 长对话场景 | 仍保持场景头+动作穿插，禁止纯对白墙超过约 15 行不停顿 |
| 动作场面 | 用短动作句，不写镜头表 |
| 多人饭局/群戏 | 点名关键说话人，路人一笔带过 |
| 时间跨场 | 必须新开 `## Sxx`，禁止在同一场内「转场到另一地点」而不换场头 |
| 电话戏 | 可用 `（电话）`；双方都在场则不要滥用电话标注 |

### 绝对禁止

- 镜头表 / 分镜表 / 景别 / 运镜 / imagePrompt / videoPrompt / sketchPrompt
- JSON、YAML、XML 包裹正文
- `（完）` 用于非终章
- 解释你是 AI、讨论写作思路、向用户提问代替写剧本

## 检查清单

- [ ] 纯文本，无 JSON / 无前言后记
- [ ] 每集以 `第N集 标题` 开头；续写/重写只含目标集
- [ ] 场景头全部为 `## Sxx | 内景/外景 · 地点 | 时间`
- [ ] 对白全部为 `角色名：台词`（可带括号状态），无引号
- [ ] 无镜头词 / 无提示词字段
- [ ] 有开场钩子与集末钩子；非终章无 `（完）`
- [ ] 角色名与 bible/前文一致；续写衔接上一集状态
- [ ] 已锁定 `bible.world.visualStyleNotes`，全篇没有真人/3D/二维等视觉形态漂移
- [ ] 多集之间体例完全一致
