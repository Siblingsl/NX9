# NX9 功能需求与解决方案：深度视频动作复刻 + 参考板热门玩法

> **文档性质**：可执行的功能需求 + 落地方案（**本阶段只定稿需求，不写实现**）。  
> **依据**：用户提供的「深度视频动作高度复刻」玩法说明 + 附图（左深度 / 右成片对照）+ 当前仓库代码行为。  
> **真相源优先级**：用户当次指令 → 本文 → `docs/skill-spec.md` / 内置 Skill 规范 → `约束开发要求.md` → 现有代码。  
> **编写日期**：2026-07-30 · 版本 **v0.3（评审稿 · 暂选方案 A + 底部工作区壳层）**  
> **落点决议**：深度视频转换**暂选方案 A**——做在参考板内部（见 §5）；独立 `depth-video` 节点（方案 C）列为后续可拆出项，本版不新建。  
> **壳层决议**：参考板改造**保持底部 Attached Workspace**，加高承载 Playbook/槽位；**不做整板弹窗**（见 §6.2）。  
> **关联能力**：参考板 `reference-board`、视频生成 `clip-gen`、既有图像深度通道 `depth-pass`、约束装配 `constraint-assembler`、技能库 Skill。

## 0. 一句话目标

把「**用深度视频锁定动作 / 用人物图锁定外貌 / 用场景图替换环境 → 一条提示词出片**」做成 NX9 内**可复用、可扩展的热门视频玩法**，并同时交付：

1. **独立完整 Skill 项目**（提示词契约 + 拼装包 + 样例，可在技能库查看修改）。  
2. **参考板改造**：从「Mood Board 堆图」升级为「**角色槽位 + 玩法配方**」，可随时挂载新热门玩法。  
3. **深度视频转换落点（暂选 A）**：转换能力做在**参考板深度槽内**（上传源视频 → 一键转深度 → 槽内预览），本版**不新建**独立深度节点。

## 1. 问题陈述（为什么要深度视频）

### 1.1 用户痛点

| 做法 | 问题 |
|------|------|
| 直接把原视频交给视频模型作参考 | 原片含服装、颜色、背景、光影等噪声，模型易被干扰 → 肢体幅度变、手脚错位、节奏跑偏 |
| 只给人物图 / 场景图、无动作控制 | 能换人换景，但**动作不可控**，难做舞蹈 / 武术 / 整活复刻 |
| 玩法散落在口头提示词 | 新手不会写约束；热门玩法无法沉淀、无法一键复用、无法版本化 |

### 1.2 解法本质（产品语义，非供应商绑定）

| 输入角色 | 职责 | 视觉直觉 |
|----------|------|----------|
| **深度视频** | 只保留灰度空间层次、人物轮廓、肢体轨迹 → **锁定动作 / 走位 / 节奏** | 左半屏黑白深度 |
| **人物参考图** | **锁定角色外貌与服装** | 右半屏成片中的角色身份 |
| **场景参考图** | **替换环境**（霓虹街、室内等） | 右半屏成片背景 |
| **提示词** | 明确各参考的绑定关系 + 画幅 / 口型 / 禁则 | 用户文案 + Skill 模板 |

> **产品原则**：深度视频是**动作控制信号**，不是成片审美来源；人物图是身份锁；场景图是环境锁。三者在参考板上**分槽位、可强制、可验收**。

### 1.3 典型成片验收场景（黄金样例）

- 素材：双人舞蹈 / 武术短片（竖屏 9:16 优先）。  
- 转换：得到与原片时长、构图节奏一致的深度视频。  
- 参考：女主图、男主图、首尔霓虹街场景图。  
- 生成：成片中动作轨迹高度跟随深度视频；角色样貌跟人物图；背景跟场景图；无字幕水印；无角色互换 / 手脚畸形。  
- 可选：片头双语台词（中文引导句 + 外语发音）口型同步——作为**进阶约束**，非 MVP 阻断项。

## 2. 现状盘点（仓库事实）

| 能力 | 现状 | 与本需求差距 |
|------|------|----------------|
| `reference-board` | Attached Workspace：上传参考图、色板、风格备注；约束走 `constraints` / `enforce`（F-017/F-032） | **无视频槽、无角色槽（深度/人物/场景）、无玩法配方、无「一键成提示词」** |
| Socket | `accepts: prompt, picture` / `emits: prompt, picture` | **未接受 / 未输出 `clip`（含深度视频）** |
| `depth-pass` | 对**单张图**做深度/法线；`flow-runner` 已接通；目录标注 P4；迁移表曾指向导演台 | **不是视频→深度视频**；职责偏空间/单帧，不宜硬塞热门舞蹈玩法 |
| `clip-gen` | 支持多参考图/参考视频 + 视频连接（含 Seedance 等模式） | 缺「深度动作复刻」结构化装配；不会自动从参考板读出角色槽 |
| Skill | 已有 Gen 拼装包机制（`templates/prompt-pack.md`） | **尚无本玩法专用 Skill**；旧 Seedance 方法论文档 Skill 已不在内置树 |
| 爆款就绪 | `has_reference_board` 仅检查「有无参考项」 | 未区分「有深度动作锁」是否就绪 |

## 3. 产品边界与非目标

### 3.1 本 epic 交付

1. 需求定稿（本文）→ 评审通过后：Skill 生成、**参考板内**深度转换 + Playbook 槽位改造、装配进 `clip-gen`。  
2. 至少 1 条可跑通主路径：**在参考板内**完成「源视频 → 深度视频」→ 槽位装配 → 提示词 → 视频生成（**单节点为主路径**）。  
3. 玩法可扩展：后续热门玩法以 **Playbook（配方）** 形式挂入参考板，不改画布拓扑也能加玩法。  
4. **本版不交付**独立 `depth-video` 画布节点；若日后方案 C 启用，须复用本版同一后端转换 API，禁止两套深度结果。

### 3.2 非目标（本版不做 / 不强绑）

- 不把某一家视频模型的营销文案写进产品主 UI；连接层仍走「设置 → 连接」的视频连接。  
- 不在本版做完整「热门视频市场 / 社区下载中心」（可预留入口）。  
- 不替代导演台批出、分镜台、剪辑台主链路。  
- 不做实时摄像头深度；输入为已上传 / 已解析的短视频素材。  
- 不做保证 100% 帧级骨骼对齐的工程承诺；验收以「动作幅度、走位、节奏高度跟随 + 身份/环境锁生效」为准。

## 4. 术语

| 术语 | 定义 |
|------|------|
| **源动作视频** | 用户上传的舞蹈 / 武术 / 整活原片 |
| **深度视频** | 由源动作视频转换得到的灰度深度序列（或等价动作控制视频），用作动作锁 |
| **角色槽（Slot）** | 参考板上带语义角色的媒体位：`depth_motion` / `character_*` / `scene` / `extra` |
| **玩法配方（Playbook）** | 一组槽位定义 + 默认提示词模板 + 校验规则 + Skill 绑定；可版本化 |
| **热门玩法** | 预置或后续可增的 Playbook（首发：`depth-action-replica`） |
| **装配提示词** | 根据槽位绑定与 Skill 模板生成的、可直接送给视频模型的最终提示词 |

## 5. 方案比选：深度转换放哪？

用户明确提问：「将舞蹈或武术素材转换成深度视频」应做到哪个节点，还是新做节点？

### 5.1 候选方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A. 塞进参考板内部** | 参考板深度槽内「上传原片 → 一键转深度」+ 原/深对照预览 | 路径短，新手一步到位；本版少一个节点 | 节点变重；失败排障耦合在板上；其他玩法若也要深度需抽公共 API | **本版暂选（生效）** |
| **B. 扩写现有 `depth-pass`** | 让 `depth-pass` 同时吃 `picture` 与 `clip`，视频输出深度 clip | 复用已有深度 API 名 | 现状是**单帧图深度**；与「热门视频动作锁」语义混杂；迁移表已弱化该 kind | **可作底层 API 参考，不作产品主入口** |
| **C. 新建节点 `depth-video`** | 独立处理节点：`clip` in → `clip`（深度）out | 职责清晰；可被多玩法复用 | 画布多节点；本版暂不引入 | **后续可选拆出**（见 §5.4） |
| **D. 放进 `clip-gen` 前置折叠面板** | 生成节点内隐式转换 | 少节点 | 黑盒；难单独预览/复用深度结果 | **不推荐** |
| **E. 放进 `codex-agent` / 外部工具** | 靠 Agent 口头调用 | 灵活 | 不可产品化验收 | **仅作高级可选，不作主路径** |

> **决议（2026-07-30）**：暂无更优产品落点时，**先按方案 A 落地**。后端转换能力仍须抽成**可复用服务 API**（板内 UI 调用），以便日后若改选 C，只加节点外壳、不重做算法与资产格式。

### 5.2 本版架构（方案 A · 生效）

```
[人物图 ×N] ──► ┐
[场景图]    ──► ┼─► [reference-board · Playbook=深度动作复刻]
[源动作视频]──► ┘         │
                           ├─ 深度槽：上传源视频 → 转深度 → 原/深对照 → 锁定 clip
                           ├─ 人物/场景槽：填图 + 锁定
                           └─ 一键装配提示词 + 多模态引用包
                                          │
                                          ▼
                                   [clip-gen]
```

**职责切割（方案 A）：**

| 组件 | 只做什么 | 不做什么 |
|------|----------|----------|
| **`reference-board`（改造）** | Playbook / 槽位；**深度槽内完成源视频上传、转换、进度、失败重试、原/深预览**；人物/场景锁；装配提示词；向下游 emit 引用包 | 不把转换逻辑散写多份；不替代 `clip-gen` 出片 |
| **后端深度转换服务** | 源视频 → 深度视频（可插拔实现）；统一资产 URL / meta | 不暴露在独立画布节点（本版） |
| **Skill `gen-depth-action-replica`** | 提示词契约、约束清单、拼装包、黄金样例 | 不执行视频转换 |
| **`clip-gen`** | 消费装配结果真正出片 | 不负责教用户摆槽位 / 转深度 |

### 5.3 方案 A 下的深度槽行为（强制）

深度槽 `depth_motion` 是本版**唯一产品入口**，须同时支持：

1. **上传源动作视频** → 显示「转换中」进度 → 成功后写入深度视频 URL，并保留源视频 URL（便于重转 / 对照）。  
2. **原 / 深对照预览**（左右或切换，对齐用户附图认知）。  
3. **直接填入已有深度视频**（跳过转换，高级用户 / 外部已转好）。  
4. **清空 / 重转**；失败展示可读原因，可重试。  
5. 转换结果写入板 data（及可选资产库），供装配与下游 `clip` emit 使用。

### 5.4 后续若改选方案 C（非本版）

若体验上参考板过重、或其它 Playbook 也要独立深度入口，可将同一后端 API 包一层 `depth-video` 节点，参考板改为「引用上游 clip / 或仍保留板内快捷」。**本版不实现该节点，文档保留比选以免遗忘。**

## 6. 参考板改造需求（核心）

### 6.1 从 Mood Board → Playbook Board

**现状**：无角色的图片墙 + 色板 + 风格备注。  
**目标**：同一节点支持多种「热门玩法」；每种玩法定义自己的槽位与提示词装配规则。

#### 6.1.1 数据模型（逻辑）

```ts
// 逻辑示意，非最终类型定稿
type ReferenceSlotRole =
  | 'depth_motion'      // 深度视频：动作/走位/节奏锁
  | 'character'         // 人物外貌锁（可多槽，带 index / label）
  | 'scene'             // 场景环境锁
  | 'style'             // 可选风格参考
  | 'extra';            // 扩展

interface ReferenceSlot {
  id: string;
  role: ReferenceSlotRole;
  label: string;          // 如「女主」「男主」「深度视频」
  mediaType: 'image' | 'video' | 'audio' | 'any';
  required: boolean;
  assetUrl?: string;      // 槽位生效资产（深度槽=深度视频 URL）
  /** 仅 depth_motion：源动作视频（转换前）；对照预览与重转用 */
  sourceVideoUrl?: string;
  /** 仅 depth_motion：idle | converting | ready | error */
  convertStatus?: 'idle' | 'converting' | 'ready' | 'error';
  convertError?: string;
  lock: boolean;          // 是否在提示词中「严格参考」
}

interface ReferencePlaybook {
  id: string;             // 'depth-action-replica'
  title: string;          // '深度视频动作复刻'
  skillId: string;        // 'gen-depth-action-replica'
  slots: ReferenceSlot[]; // 模板槽
  defaultAspect?: string; // '9:16'
  enforce?: boolean;
}

interface ReferenceBoardData {
  playbookId: string;
  slots: ReferenceSlot[];
  userPromptExtras?: string;  // 用户补句（场景描述、台词等）
  assembledPrompt?: string;
  palette?: string[];
  styleNotes?: string;        // 兼容旧 Mood Board
  enforce?: boolean;
}
```

#### 6.1.2 首发 Playbook：`depth-action-replica`

| 槽位 | 角色 | 媒体 | 必填 | 提示词语义 |
|------|------|------|------|------------|
| 深度视频 | `depth_motion` | video | 是 | 全部动作、走位、身体姿态、互动、节奏严格跟随；不得自行修改 |
| 人物 1…N | `character` | image | ≥1 | 外貌与服装严格参考对应图；全程样貌一致 |
| 场景 | `scene` | image | 建议 | 背景环境替换为该场景 |
| 用户补句 | text | — | 否 | 风格（如韩式 MV）、台词、画幅、禁则补充 |

#### 6.1.3 可随时增加热门玩法（扩展机制）

后续新玩法 = 新 Playbook 定义（+ 可选新 Skill），**不新造参考板节点**：

| Playbook 示例（预留，本版可不实现） | 要点 |
|--------------------------------------|------|
| `depth-action-replica` | 本版主交付 |
| `first-last-frame` | 首尾帧锁 + 中间运动 |
| `ref-video-restyle` | 原视频风格迁移（无深度） |
| `multi-character-swap` | 多角色换人 |
| `dialogue-lip-lock` | 台词口型强化包 |

**扩展验收**：技能库 / 配置增加一个 Playbook 后，参考板下拉可选；槽位 UI 按定义渲染；装配走对应 Skill；**无需改 `clip-gen` 主代码**（仅通用消费结构化引用包）。

### 6.2 参考板 UI 要求

#### 6.2.0 壳层决议（2026-07-30）

| 选项 | 结论 |
|------|------|
| 底部 Attached Workspace（现有） | **本版采用**：与画布连线上下文同在，和 `clip-gen` 等生成节点交互一致 |
| 整板弹窗 / ScreenModal | **本版不做**：参考板是配置节点，不是编剧台式整页作业台 |
| 对照预览轻量放大 | **允许**：仅「原 / 深对照」可点开浮层放大，不是整板 Modal |

**实现约束**：

- 继续挂在节点底部 `ComposerWorkspaceShell` / Attached Workspace，`workspaceType: board` 不变。  
- 现有 `max-h-[360px]` **不够**；须加高到约 `420–540px` 或 `min(58vh)` 量级（可对齐 `VideoWorkspace` / `ExportWorkspace`），以容纳 Playbook + 多槽 + 装配区。  
- 信息架构优先压缩密度（槽位网格、折叠次要操作），而不是换弹窗壳。  
- 日后若玩法过多、底部再加高仍挤爆，再评估「展开编辑」；**不作为本版默认路径**。

#### 6.2.1 工作区内内容

1. **玩法切换**：顶部 Playbook 选择器（首发仅一个也可，但结构必须预留）。  
2. **槽位卡片**：每槽显示角色名、必填角标、缩略图/视频预览、替换/清空、锁定开关。  
3. **深度槽（方案 A 主入口）**：  
   - 主操作：「上传源视频并转换为深度」；转换中禁用重复提交并显示进度。  
   - 成功后：**原 / 深对照预览**（工作区内小预览；可点开轻量浮层放大）；深度 URL 写入 `assetUrl`，源片写入 `sourceVideoUrl`。  
   - 次操作：直接上传/填入已有深度视频；重转；清空。  
   - 失败：槽内展示错误文案 + 重试（见 §5.3）。  
4. **装配区**：一键「生成提示词」→ 预览可编辑 → 确认后写入 `assembledPrompt` 并 emit。  
5. **强约束**：`enforce=true` 时，缺必填槽、深度仍在 converting、或装配失败 → 下游生成应阻断并提示补齐（对齐 F-017 精神，扩展到槽位级）。  
6. **兼容**：旧工程仅有 `boardImages` / `styleNotes` 的，进入板时映射为「通用 Mood」玩法或只读迁移提示，不丢数据。

### 6.3 Socket 升级（必须）

| 方向 | 现况 | 目标 |
|------|------|------|
| accepts | `prompt, picture` | 增加 `clip`（接收上游深度视频 / 源视频） |
| emits | `prompt, picture` | 增加 `clip`（把深度视频与引用包传给 `clip-gen`）；`prompt` 输出装配后的提示词 |

下游 `clip-gen` 须能识别「来自参考板的多模态引用包」（深度视频 + 人物图 + 场景图 + 锁语义），而不是只吃一张 mood 图。

## 7. 深度转换能力（方案 A：板内能力 + 后端服务）

> **本版不新建**画布节点 `depth-video`。产品入口 = 参考板深度槽；执行体 = 可复用后端 API。

### 7.1 后端服务（逻辑）

| 项 | 内容 |
|----|------|
| 能力名（建议） | `convertDepthVideo` / `POST …/depth-video`（最终路径实现时定） |
| 输入 | 源动作视频 URL（或上传文件）；可选参数（分辨率、最大时长） |
| 输出 | 深度视频 URL、`meta`（时长、分辨率、方法、源 URL） |
| 调用方 | **仅**参考板深度槽 UI（本版）；日后方案 C 节点须共用此 API |

### 7.2 功能需求（板内兑现）

1. 参考板深度槽上传源视频后一键转换。  
2. 进度与失败原因可读；可重试。  
3. **对照预览**：左右或切换「原片 / 深度」。  
4. 成功结果写入槽位并参与下游 `clip` emit；可选进资产库。  
5. 长视频时长/大小上限与清晰报错（建议首版 ≤30s 或 ≤60s，见 §12）。  
6. 亦支持跳过转换、直接填入已有深度视频。

### 7.3 与旧 `depth-pass` 关系

| | `depth-pass` | 本版深度转换（板内） |
|--|--------------|----------------------|
| 输入 | 图 | 视频 |
| 输出 | 深度图 / 法线图 | 深度视频 |
| 产品叙事 | 空间/单帧控制（历史能力） | 热门动作复刻控制信号 |
| 本 epic | 可保留底层/隐藏 | **主推产品入口（在参考板内）** |

禁止在文档与 UI 中把「单帧 depth-pass」与「深度视频动作锁」混称为同一个能力糊弄用户。

### 7.4 方案 C 预留（非本版范围）

独立节点 `depth-video` 仅作后续可选；启用条件见 §5.4。本版 REQ 与验收**不以**该节点存在为准。

## 8. Skill 需求：`gen-depth-action-replica`

### 8.1 形态（强制）

独立完整 Skill 项目，遵守 `docs/skill-spec.md`：

```
skills/gen-depth-action-replica/
  metadata.json
  SKILL.md
  examples/input.md
  examples/output.md
  references/
  templates/
    prompt-pack.md      # 拼装包：quality / constraints / template / overlay / slot_rules
  scripts/
  tests/
```

- `lane`: `builtin`  
- `nx9.category`: gen  
- 技能库可查看 / 修改 `SKILL.md` 与 `prompt-pack.md`（与现有 Gen Skill 编辑体验一致）

### 8.2 Skill 做什么

1. **说明**为何用深度、各槽职责、禁止项。  
2. **`prompt-pack.md` 模板**产出类似用户示例的装配文案，变量含：场景描述、人物槽标签、深度引用标签、画幅、禁则、可选台词段。  
3. **约束清单**：身份不互换、手脚不畸形、无字幕水印、动作不得擅自改编等。  
4. **黄金样例**：输入槽位描述 → 输出完整提示词（可用用户提供的韩式 MV 例改写为 NX9 中性样例）。

### 8.3 提示词装配契约（逻辑）

装配结果必须显式包含：

1. 风格 / 场景一句话。  
2. 每个角色：`外貌和服装严格参考@人物槽N`。  
3. 动作总锁：`全部动作、走位、身体姿态、互动、节奏严格参考@深度视频，完整复刻，不得自行修改`。  
4. 出场顺序跟随深度视频（若多角色）。  
5. 技术约束：画幅、一镜到底（若勾选）、无字幕/文字/水印、无错位/互换/畸形。  
6. 用户补句（台词、情绪）插入约定位置，不得冲掉锁句。

### 8.4 与视频连接的关系

Skill **不**内置 API Key；出片走当前视频模态的**活跃连接**。文档与 UI 缺连接时应引导「设置 → 连接 → 视频」。

## 9. 端到端用户流程（验收主路径）

### 路径 P0（方案 A · 本版主路径）

1. 画布放置 `reference-board`，选择玩法「深度视频动作复刻」。  
2. 深度槽：上传舞蹈/武术源视频 → 一键转深度 → 原/深对照确认。  
3. 上传女主/男主图、场景图；按需打开锁定。  
4. （可选）填写补句：风格、台词、画幅。  
5. 点「生成提示词」→ 预览 → 确认。  
6. 连线至 `clip-gen`（或制作台等价入口）→ 使用当前视频连接出片。  
7. 成片目视：动作跟随深度；人像跟参考；背景跟场景。

### 路径 P0b（已有深度视频）

1. 参考板深度槽直接填入已转好的深度视频（跳过转换）。  
2. 其余同 P0 步 3–7。

## 11. 验收标准（DoD）

1. **文档**：本文评审通过（角色槽、**方案 A 落点**、Skill 边界无歧义）。  
2. **Skill**：目录齐全；改 `prompt-pack` 后下次装配文案变化可感知。  
3. **板内转换**：仅用参考板深度槽即可完成源视频 → 深度视频，并原/深对照预览（**不要求**独立 `depth-video` 节点）。  
4. **壳层**：改造后的参考板仍在**节点底部工作区**完成填槽与装配；**无**整板弹窗；高度足以容纳 Playbook + 槽位 + 装配区。  
5. **参考板**：深度 + 人物 + 场景填齐后，一键得到含「深度锁 / 人物锁 / 场景锁」的提示词。  
6. **出片**：同一组输入，动作明显跟随深度而非「自由发挥跳舞」；换人物图后身份变、动作骨架仍跟深度。  
7. **扩展**：再增加一个空壳 Playbook 仅改配置即可出现在参考板下拉（实现阶段用最小 stub 证明）。

## 14. 结论（给评审的一句话）

- **做成 Skill**：`gen-depth-action-replica`（独立完整项目 + 拼装包）。
