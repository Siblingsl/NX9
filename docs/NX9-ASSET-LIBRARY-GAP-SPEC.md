# NX9 素材库 · 功能缺失与协作规格

> 状态：缺口规格（供排期与实现对齐，**本文不改代码**）  
> 范围：全局 `AssetLibraryModal` 全子库 + 设定就绪预检 + Mention / AssetRef 消费链 + 健康检查 + **UI/原型与操作动线**  
> 依据：仓库现行代码与 `docs/`（角色详析见 `NX9-ASSET-LIBRARY-CHARACTER-ANALYSIS.md`）  
> 日期：2026-08-11（同日增补 §6 动线规格）

## 0. 怎么读本文

| 符号 | 含义 |
|------|------|
| **缺失** | 产品主链需要、代码无独立能力或仅为占位 |
| **半成品** | UI/字段在，校验、消费或协作断点未齐 |
| **缺陷伪装成完成** | 台账已标完成，但逻辑不可信（如 F-051 服装比对） |
| **协作要求** | 该能力必须与上下游如何对接才算「可用」 |
| **动线 / UX** | 允许适度优化壳层与原型，但必须以操作更短、语境不丢、反馈诚实为约束（见 §6） |

**一句话总判断**：素材库骨架（开库 → 建档 → `@类型:名` → 注入 Prompt）已齐；真正闭环的是**角色**与**场景**。服装编辑面强、预检/分镜引用弱。镜头/情绪/钩子是可维护词典。声音可用但与角色参考音、`voice.profiles` 三角未产品化。**道具被预检承认却没有子库**。健康条文案超前于实现。壳层可用但偏「长滚动编辑器」：健康不可点、主操作分散、预检往返易丢语境——**功能补齐时须同步修动线，禁止只堆字段**。

## 1. 目标闭环（缺什么之前，先定「应如何配合」）

### 1.1 权威边界（SSOT）

```
编剧台 Bible / ScreenplayPackage     ← 叙事草稿（默认可不同步入库）
        │ 设定就绪 · 同步 / 拆分 syncAssets
        ▼
素材库（私有工作区 + 可选公共库）     ← 视觉/听觉一致性权威编辑面
        │ 按名/ID 绑定 + @Mention + AssetRef
        ▼
分镜台 → 导演台 → 图像/视频/配音节点   ← 生产消费面
```

规则：

1. **库是生产权威**：定妆、设定板、锁定 Prompt、参考音以库为准。  
2. **Bible 是叙事草稿**：未同步则分镜按名绑定失败属预期，不是库坏了。  
3. **镜表绑定是桥**：`characterNames` / `sceneName` → 库 ID；别名可辅助，但失效引用必须可解释、可修复。  
4. **Mention 与 AssetRef 互补**：文本里 `@类型:名` 适合自由 Prompt；节点条上的 AssetRef 适合结构化挂载。二者解析结果应一致。  
5. **设定就绪是闸门**：缺角色/场景/视觉门槛应拦；服装/道具缺口应对照**对应子库**，而不是角色名集合或永远全缺。

### 1.3 统一协作契约（所有子库共用，当前多数未齐）

每个「可生产」子库条目理想上具备：

| 契约项 | 用途 | 现状 |
|--------|------|------|
| 稳定 `id` + 展示名 `label/name` | 绑定与改名策略 | 有；改名后引用修复弱 |
| `@类型:名` | Prompt 注入 | 有协议；消费面不一致（见 §4.2） |
| 生产 Prompt（可锁定） | 一致性 | 角色/场景/服装有锁；镜/情/钩多为字段无锁语义 |
| 至少一张参考媒体（图或音） | img2img / 克隆 | 角色/场景/服装/声音有；镜/情/钩弱 |
| 健康指标 | 重复/未用/缺 Prompt/失效引用 | 仅角色、场景真算 |
| 与设定就绪对照 | 缺口 chip → 正确 Tab + 建档 | 角色/场景可用；服装比对错；道具无库 |
| 关系可查询 | 「谁引用了我 / 我引用了谁」 | 「影响分析」不可点 |
| 私有 ↔ 公共复制 | 跨项目复用 | 有；公共深化设定板摩擦大 |

## 2. 已有子库清单与成熟度

| Tab | Kind | 成熟度 | 一句话 |
|-----|------|--------|--------|
| 角色 | `character` | 主路径可用 | 最完整；仍有 Mention 双协议、Bible 单向、制作台瘦客户端 |

| 道具 | `prop` | 主路径可用 | 见 CSP redesign |

## 3. 按子库列出的功能缺失（逐项）

### 3.1 角色（相对完整，缺口偏协作与收口）

对照 `NX9-ASSET-LIBRARY-CHARACTER-ANALYSIS.md` §13，下列为**仍缺失或未收口**的功能：

| ID | 缺失功能 | 说明 | 应如何配合 |
|----|----------|------|------------|
| C-01 | Mention 单协议 | `@角色:名` 与裸 `@名` 并存，绑定失败与「失效引用」虚高 | 全站 Prompt 解析统一；旧 `@名` 仅兼容层并提示升级；健康检查按同一规则计数 |
| C-02 | Bible ← 库正式回写 | 同步入库不覆盖已有；库侧深化后无法正式回写 Bible | 提供「推送到 Bible 草稿」或「对比 diff 后合并」；避免两套真相长期漂移 |
| C-03 | 制作台 = Modal 能力对齐 | AssetsHub 无设定板一键、无 Creative 全字段、无公共库 | 制作台只做瘦客户端 +「在素材库打开」深链；禁止第二套编辑语义 |
| C-04 | 失效引用一键修复 | 健康条只显示数字 | 点击「失效引用」→ 列表（镜号、旧名）→ 从库挑选重绑或改镜表名 |
| C-05 | 「影响分析」面板 | UI 为不可点 `<span>` | 打开关系图：角色 → 分镜 shots / 节点 AssetRef / 导演台占用 |
| C-06 | Prompt 版本 / 漂移 diff | 文案声称「Prompt 漂移」，无检测 | 锁定前后版本对比；或至少记录 `promptVersion` + 上次锁定摘要 |
| C-07 | 从库挑选绑定镜表角色 | 主要靠名称/别名自动匹配 | 分镜侧「从角色库选择」写入 id+名，降低错别字成本 |
| C-08 | 公共库设定板零摩擦 | 公共只读，须先复制到私有才能一键设定板 | 复制后自动打开私有条目；或公共允许「生成到私有副本」 |
| C-09 | 3D 舞台 ↔ 2D 定妆强制校验 | 舞台物体与定妆图无一一校验 | 导演台健康：缺参考图/缺设定板的角色不可标记「可拍」 |
| C-10 | 昵称 placeholder 误导 | 「林先生 / 老林」易被当成已填 | 空态与 placeholder 视觉区分；健康检查不计 placeholder |
| C-11 | 设定板独立可用性提示 | 强依赖画布 picture-gen | 无图像节点时给出明确引导（创建临时节点或库内异步任务），不静默禁用 |

### 3.2 服装

| ID | 缺失功能 | 说明 | 应如何配合 |
|----|----------|------|------------|
| Cos-01 | **预检对照服装库**（缺陷） | `missingCostumes` 用**角色名集合**过滤抽取到的服装片段，几乎永不正确 | 对照 `workspaceItems` 中 `kind==='costume'` 的 label；缺口 chip → 服装 Tab 并建议「一键建档」 |

### 3.8 道具（建议新增子库 · P0）

**现状事实**：

- `extractPropNames` 从 Bible 场景摘要抽「道具/物品/摆设」  
- `missingProps = requiredProps`（**从不对照任何库**）  
- 缺口 chip 跳转**场景** Tab（台账明确「无独立 prop tab」）  
- 场景仅有 `props: string[]`；`script-consistency` 亦有 prop 类检查但无库实体

| ID | 缺失功能 | 说明 | 应如何配合 |
|----|----------|------|------------|
| Prop-01 | 独立 Tab + Kind | `AssetLibraryKind` / `BacklotTemplateKind` 增加 `prop`；`ASSET_LIBRARY_TABS` 增加道具 | 与角色/场景同级 CRUD、软删、公私 scope |
| Prop-02 | 档案字段 | 名、外观 Prompt、参考图、所属场景、标志细节、锁定 | 对齐服装轻量版；不必上完整设定板五分类 |
| Prop-03 | `@道具:名` | `ASSET_KIND_MENTION_PREFIX` + `parseAssetMentions` | 分镜 GLOBAL_MENTION、picture/clip enrich 全开 |
| Prop-04 | 预检对照本库 | `missingProps` 过滤已存在 label | chip → `tab:'prop'`；可选一键建档 |
| Prop-05 | 场景引用 | 场景「固定道具」→ propIds | 环境 Prompt / scene-card-prompt 读实体 Prompt+图 |
| Prop-06 | 分镜 / 导演引用 | 镜表或导演台可挂本镜关键道具 | 连续性检查（`consistency-repair` category prop）对照库 id |
| Prop-07 | 健康检查 | 重复、未使用、缺图、失效场景绑定 | 纳入健康条，去掉假零 |
| Prop-08 | 同步策略 | Bible 抽名 → 建议建档，不自动污染库 | 与角色同步同哲学：显式确认 |

## 4. 跨切能力缺失（所有子库共用）

### 4.1 素材健康检查

**已实现（仅角色 / 场景 Tab）**：重复、未使用、缺 Prompt、未锁定、失效引用（相对当前镜表）。

**缺失 / 占位**：

| ID | 缺失 | 应如何配合 |
|----|------|------------|
| H-01 | 服装 / 镜头 / 情绪 / 钩子 / 声音（及未来道具）真指标 | 每 Tab 独立 `issues` 计算器，禁止假零 |
| H-02 | 「素材污染」检测 | 定义可计算规则（同图多条目、空 Prompt 已上镜等） |
| H-03 | 「Prompt 漂移」检测 | 锁定快照 vs 当前；或与最近一次出图所用 Prompt 比对 |
| H-04 | 「影响分析」可点击 | 失效引用列表 + 关系图；支持跳转分镜/节点 |
| H-05 | 跨 Tab 总览 | 顶栏一次看到「全库阻塞项」，不只当前 Tab |
| H-06 | 修复动作 | 每类问题至少一种：重命名合并、绑定、补 Prompt、打开条目 |

### 4.2 Mention 与 AssetRef 消费一致性

| ID | 缺失 | 应如何配合 |
|----|------|------------|
| M-01 | 分镜 `GLOBAL_MENTION_KINDS` 补齐 `costume`（及未来 `prop`） | 与 `parseAssetMentions`、picture-gen 对齐 |

## 6. UI / 原型与操作动线（可优化，但必须以动线舒适为约束）

> **原则**：允许适度优化信息架构与视觉层次，**禁止**为「好看」打断既有生产闭环（开库 → 选条目 → 补媒体/Prompt → 锁定 → 回分镜/出图）。任何 UI 改动须能在本节动线表里指出「少点几次 / 少滚一次 / 少猜一步」。

### 6.1 现状动线诊断（对照现行 Modal）

当前壳层（`AssetLibraryModal`）大致为：

```text
顶栏：标题 · 私有/公共 · 回收站 · 关闭
横滑 Tabs（7 kind）
健康检查条（多为不可点 chip；非角/场假零）
搜索 + 计数 + 新建（+ 服装批量设定板）
左列表（纯文字） | 右详情（长滚动 DetailSection 堆叠）
```

| 摩擦点 | 现象 | 动线代价 |
|--------|------|----------|
| 视口偏紧 | 约 `960×720` 固定模态 | 角色/场景设定板与多参考图需大量纵向滚动；对照媒体与填 Prompt 来回跳 |
| Tab 扁平 | 生产实体与词典类平铺一排；道具落地后更挤 | 找错类、切 Tab 清 `editId` 丢上下文 |
| 健康条占位 | 「影响分析」不可点；假零抢注意力 | 用户学到「数字不可信」→ 真指标上线后仍被忽略 |
| 列表无缩略图 | 左栏仅 label | 视觉资产靠名猜；定妆/场景图无法一眼扫 |
| 详情无分区导航 | 角色：一致性→设定板→参考→表情… 一长串 | 「只想锁 Prompt / 换绑服装」仍要滚屏 |
| 主操作分散 | 「一键设定板」在详情内、「生成定妆图」挂在 Modal 外层 | 同类生成动作不在同一视觉锚点 |
| Scope 切换粗暴 | 切私有/公共清空选中与搜索 | 公共预览→复制到私有后需重新找条目 |
| 回收站整页替换 | 无面包屑级返回语境 | 误点后丢失「刚才在编哪条」 |
| 预检深链半通 | 可带 tab/query；道具误进场景；缺「建议建档」表单前置 | 设定就绪 → 库 → 回来 往返成本高 |

### 6.2 目标信息架构（原型方向，非大重构）

**保留**：单一全屏模态作为库 SSOT 编辑面；左列表 + 右详情；私有 / 公共 scope。  
**优化**：把「找得到 → 改得完 → 修得掉 → 回得去」做成短动线。

```text
┌─ 顶栏：库名 · 项目 · [私有|公共] · 全库阻塞摘要 · 回收站 · 关闭
├─ 左侧导航（可分组，非仅横滑 pill）
│    生产资产：角色 / 服装 / 场景 / 道具 / 声音
│    生产资产：角色 / 服装 / 场景 / 道具 / 声音（私有 + 公共）
│    语言词典：镜头 / 风格（仅公共；私有顶栏不展示）
│    （情绪、爆点退出主导航；爆点 SSOT=编剧 brief.hooks）
├─ 工具条：搜索 · 健康筛选 · 仅收藏/缺图/未锁 · 新建 ·（上下文批量动作）
├─ 主区
│    左：缩略图列表（状态角标：锁 / 缺图 / 失效）
│    右：详情
│         ├ 粘性条：名 · 锁定 · 复制 @提及 · 主生成 · 更多
│         └ 分区锚点：档案 | 媒体 | Prompt | 关系 | 高级
└─ 可选右抽屉：影响分析 / 失效引用修复（不盖住主编辑）
```

分组导航与详情分区是**动线优化**，不是换产品模型；Kind 与 Mention 协议仍以 §1～§3 为准。

### 6.3 核心操作动线（目标态必须舒适）

以下动线验收时按「步骤数 / 是否丢上下文 / 是否需记忆隐藏入口」打分。

#### 动线 L1：设定就绪缺口 → 补齐 → 回预检

```text
预检 chip「缺服装：旗袍」
  → 打开库且 tab=costume、query=旗袍（或直接打开「建议建档」预填单）
  → 保存 +（可选）生成设定板
  → 顶栏/toast「返回设定就绪」或自动关闭库并刷新就绪态
```

| ID | UI 要求 |
|----|---------|
| UX-01 | 深链必带 `tab + query/itemId`；道具不得进场景（绑 U-02 / R-04） |
| UX-02 | 缺口「一键建档」打开轻量表单（名已填），保存后留在新条目详情，不甩回空列表 |
| UX-03 | 从预检进入时显示语境条：「来自设定就绪 · 返回」，避免用户关模态后找不到预检 |

#### 动线 L2：选条目 → 补媒体 / Prompt → 锁定

```text
列表点选（缩略图可辨）
  → 详情粘性条始终可见「锁定 / 复制@ / 主生成」
  → 分区锚点一键跳到「媒体」或「Prompt」
  → 锁定后列表角标立即反映
```

| ID | UI 要求 |
|----|---------|
| UX-04 | 详情顶粘性操作条（锁、@、主生成、删除进更多）；生成定妆/设定板归入同一「主生成」菜单，去掉 Modal 外挂重复按钮 |
| UX-05 | 长详情用页内锚点或二级 tab（档案 / 媒体 / Prompt / 关系），默认落在「当前最缺」分区（无图优先媒体，无 Prompt 优先 Prompt） |
| UX-06 | 左列表展示主参考缩略图 + 状态点（缺图 / 未锁 / 有健康问题） |

#### 动线 L3：健康问题 → 过滤列表 → 修复 → 复核

```text
点健康 chip「失效引用 3」
  → 列表仅显示相关条目或打开修复抽屉
  → 逐条重绑 / 合并重名
  → chip 数字下降；可「下一项」
```

| ID | UI 要求 |
|----|---------|
| UX-07 | 健康 chip **可点**：过滤列表或打开问题队列（绑 H-04 / H-06） |
| UX-08 | 假零 Tab 不展示伪装指标；未实装时显示「本类检查即将上线」或折叠，避免学成「无视数字」 |
| UX-09 | 「影响分析」改为按钮，右侧抽屉展示引用方，支持跳转分镜/节点 |

#### 动线 L4：公共预览 → 复制私有 → 继续深化

```text
公共条目预览（只读）
  → 「复制到项目并编辑」
  → 自动切私有 + 选中副本 + 打开可写详情（设定板可用）
```

| ID | UI 要求 |
|----|---------|
| UX-10 | 复制后不丢选中（绑 C-08）；toast 含「已开始编辑副本」 |
| UX-11 | 切 scope 时若目标库存在同 id/同源副本，尽量保留选中；否则保留 query |

#### 动线 L5：库内关系跳转（角色 ↔ 服装 ↔ 场景 ↔ 道具）

```text
角色详情「绑定服装」→ 下拉选择或「在服装库打开」
服装详情「被哪些角色使用」→ 点击跳到该角色并高亮绑定区
场景「固定道具」→ 芯片跳转道具详情 / 建议建档
```

| ID | UI 要求 |
|----|---------|
| UX-12 | 跨 Tab 跳转保留返回栈（最多 1～2 层：「返回角色·林晓」） |
| UX-13 | 关系区用芯片而非纯 id 文本；空态给「去建档」CTA |

#### 动线 L6：Desk 深链进库再回去

```text
分镜/导演/配音「打开素材库」
  → 带 tab+itemId
  → 编辑后关闭，焦点回到原 Desk 控件（若可）
```

| ID | UI 要求 |
|----|---------|
| UX-14 | 统一 `navigateRequest` 契约：scope/tab/itemId/query/returnHint（绑 U-03） |
| UX-15 | 制作台入口文案诚实：能力子集 +「在完整素材库打开」（绑 C-03 / U-01） |

### 6.4 视觉与布局优化边界（适当优化，勿过度设计）

| 可做 | 不做 |
|------|------|
| 略增大默认模态（如接近 `min(1120px,96vw) × min(820px,92vh)`），大屏更宽 | 拆成独立路由 App 或多窗口体系（除非产品另立里程碑） |
| 左栏缩略图、状态角标、健康过滤 | 卡片瀑布流、仪表盘式多统计抢第一眼 |
| Kind 分组导航 + 详情分区锚点 | 为每个 kind 做完全不同的页面骨架 |
| 粘性主操作条、语境条（来自预检） | 多层悬浮徽章、装饰性动效干扰编辑 |
| 空态说明「下一步」（新建 / 从预检导入 / 从公共复制） | 空态只写一句「选择或新建」 |
| 回收站用层叠面板或明确「← 返回素材库」并恢复 tab/item | 用回收站替换后无状态恢复 |

风格约束：沿用 NX9 现有 `surface / line / brand / ink` 语义色与圆角控件；**不**引入新的紫色光效风或仪表盘卡片堆砌。动线清晰优先于装饰。

### 6.5 与功能缺口的协作关系

| UI 项 | 依赖或解锁的功能 ID |
|-------|---------------------|
| UX-01～03 | R-04、U-02、Prop-04、Cos-01 |
| UX-04～06 | C-11（设定板引导）、各子库媒体字段 |
| UX-07～09 | H-01、H-04、H-06；未实装前先做 UX-08 诚实化 |
| UX-10～11 | C-08、S-02 |
| UX-12～13 | Cos-05、Prop-05、Scn-01 |
| UX-14～15 | U-01、U-03、C-03 |

**落地建议**：P0 功能（道具库、服装预检、Mention）可并行做 **UX-01/02/08**（深链与诚实空态，改动面小、立刻减挫败）；大布局（分组导航、粘性条、缩略图列表）放在 P1，与健康可点修复一起做，避免假指标配精美壳。

### 6.6 UI 验收（动线舒适的最低条）

1. **预检往返**：从任一缺口 chip 进入库，≤2 次点击到达可编辑表单或正确条目；有「返回就绪」入口。  
2. **锁定闭环**：打开未锁条目后，不滚动也能看到并完成「锁定」。  
3. **健康可信**：可见的数字均可点或明确标注未启用；无假零。  
4. **跨库跳转**：角色→服装→返回角色，选中态与滚动位置可恢复或有返回栈。  
5. **公共深化**：复制到私有后直接进入可写详情，无需重新搜索。  
6. **不丢语境**：切 Tab / 开回收站 / 关再开（同会话深链）尽量恢复 scope+tab+item。

## 8. 验收视角（功能算「完成」的最低条）

对**任一**子库声称完成时，至少同时满足：

1. **能建档**：私有 CRUD + 软删；公共复制策略清楚。  
2. **能引用**：`@类型:名` 在分镜与主生成节点可插入且 enrich 生效。  
3. **能预检**（若该类型出现在设定就绪）：缺口对照本库，chip 打开正确 Tab，可一键建档。  
4. **能健康**：本 Tab 指标非假零；至少「缺 Prompt / 失效引用」两类可点。  
5. **有协作说明**：在本文场景 A–F 中能指出上下游各一步。  
6. **能动线**：满足 §6.6 中与该子库相关的条目（至少 L2 锁定闭环 + 若走预检则 L1）。

道具库未建前，F-051 道具部分只能算「缺口展示」，**不能**算「可关闭的资产完备」。

## 10. 一句话产品定义（缺口语境）

**素材库应成为「可预检、可引用、可修复」的项目资产中枢：每个上镜实体（人、服、场、道、声）有库位；词典类（镜、情、钩、风格）可维护且与分镜/生成同协议；健康检查与设定就绪说真话并指向修复动作；编辑壳层让补齐与锁定走短动线，而不是长滚动碰运气。**

当前最大结构洞是**道具无库却已进入预检话术**；最大信任洞是**服装预检比对错误**与**非角场 Tab 健康假零**；最大协议洞是**分镜 @ 与图像 @ 种类不一致**及 **Mention 双协议**；最大体验洞是**健康不可点、详情缺粘性主操作、预检往返语境易丢**。
