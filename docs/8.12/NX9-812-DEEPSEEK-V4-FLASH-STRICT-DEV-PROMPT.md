# 单文档标准流程（每份文档强制执行）

## A. 开工前 · 读档与建账（禁止写代码）

对**当前文档**执行：

1. **全文阅读**该 md（含「已收口」「范围外」「验收口诀」「建议顺序」）。  
2. 提取**全部待办票**，生成台账表（必须输出给用户看）：

```markdown
## [文档名] 票项台账

| 票号 | 优先级 | 符号 | 一句话 | 锚点路径 | 文档验收要求 | 状态 |
|------|--------|------|--------|----------|--------------|------|
| ... | P0 | ❌ | ... | apps/web/... | ... | 待做 |
```

3. **逐票读锚点代码**（用 Read/Grep，禁止臆猜）。  
4. 若票内验收模糊，以文档「验收 / 收口 / 四问（触得到/传得真/跑得完/流得回）」为准；仍不明则**最小实现 + 在输出中列出待确认点**，但不得空实现。

## B. 实施中 · 逐票闭环（禁止跳票）

对台账中每一行 **状态=待做** 的票，严格按序：

1. **复述**：本票要消灭的「撒谎 / 断点 / 串台」是什么。  
2. **改代码**：最小 diff；复用现有函数（如 `patchShotOnChainGraph`、`findDeskIdForShot` 等），禁止平行造第二套写回。  
3. **补测例**：文档要求或行为可回归的，补/改 vitest；至少跑与改动相关的测试。  
4. **本地验证命令**（能跑则跑，失败必须修或说明环境阻塞）：
   - `pnpm exec vitest run <相关测试文件>`
   - 必要时 `pnpm --filter @nx9/web typecheck` 或仓库既有 typecheck 命令  
5. **更新台账状态**为「待自检」→ 完成下列 C 节三项自检 → 「已闭环」。

**禁止**：一次 PR 声称关闭 10 张票但只改了注释；禁止「后续再做测试」。

## C. 完票自检（每一票完成后立刻做）

### C1. 功能自检（必须可证伪）

- [ ] **跑得完**：执行结束状态 honest（success/error/skipped），无假绿、无空产物冒充成功  
- [ ] **流得回**：产物、镜表、节点 content、taskId、usedAssetIds、revision pin 等按文档回到正确 SSOT  
- [ ] **回归**：文档 §「已收口」相关路径快速冒烟，确认未打回  

### C2. UI / 原型自检（凡涉及界面必做）

- [ ] 无组件重叠、遮挡、裁切、z-index 错乱
