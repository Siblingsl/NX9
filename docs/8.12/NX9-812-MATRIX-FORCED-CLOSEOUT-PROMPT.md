1. **Source of Truth**：用户当次指令 → 本矩阵 → 矩阵引用的审计原文验收句 → `约束开发要求.md` → 现行代码。

5. **最小 diff**：只改当前票必需文件；匹配周边风格；不做无关重构（巨石拆分票除外，拆分时也必须保持行为不变 + 测例全绿）。

# 单票标准流程（每一矩阵行强制执行）

## A. 开工前（禁止写代码）

对**当前票**输出：

```markdown
## 票 [票号] 开工卡

- 矩阵状态：部分完成 | 未完成
- 来源文档：...
- 矩阵「仍缺 / 缺口」原文：...
- 锚点文件（Grep/Read 核实后的路径）：...
- 验收标准（可证伪）：...
- 依赖：无 | 产品拍板 | 美术资产 | 其他票
- 计划 diff 范围：...
- 回归测例：...
```

未输出开工卡就改代码 = 失败。

## B. 实施中

1. **复述**本票消灭的断点 / 半闭环 / 工程债是什么。  
2. **最小 diff** 改代码；复用存量写回/runner；禁止平行第二套真相源。  
3. **补测例**：凡可单测的必须补；UI 票必须写清浏览器步骤并实际执行（或明确环境阻塞原因）。  
4. **自检三件套**全部通过才允许改矩阵状态：  
   - **功能自检**：按验收句逐条打勾，附文件路径与行为前后对比  
   - **UI/原型自检**（有界面时）：无错位、无双标题不一致、无「关了模式状态还粘着」、无假绿/假成功文案  
   - **矩阵完票自检**：该行是否已无「仍缺」；相关同源票（如 DR-08≈VG-48）是否一并关闭或交叉引用  

## C. 完票输出格式（强制）

```markdown
### ✅ 完票 [票号]

- 矩阵原状态 → 新状态：
- 改动文件：
- 测例命令与结果：
- UI 复验步骤与结果：（无 UI 写 N/A）
- 同源票交叉关闭：
- 未做/阻塞：（无则写无）
```
