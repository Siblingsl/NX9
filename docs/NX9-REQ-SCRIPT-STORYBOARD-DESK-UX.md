## AI 速读卡

- 产品一句话：在 NX9 主链上补齐「按集数生成/续写剧本」，并收口分镜台只做线稿构图、导演台只做彩色关键帧批出。
- 核心循环：选题集数 → 生成/续写剧本 → 拆镜与线稿 → 确认本集 → 导演台批出彩色关键帧。
- 目标平台：NX9 Web 桌面端画布 Desk（编剧台 / 分镜台 / 导演台）。
- 硬约束：首次生成与续写必须可选集数；镜表无试出；底栏无四按钮；预览无 3D；模型在 Tab 外；分镜只线稿、彩图只导演台。
- 推荐默认：首次生成默认选 3 集；续写默认 1 集；宫格线稿可作构图次主按钮。
- 发挥空间：线稿预览网格视觉、按钮分组、空态文案与微动效（不得改变数据契约与入口位置）。
- P0 验收：集数弹层可用；续写可选 N 集并追加；无试出/无底栏四按钮/无预览 3D；模型在 Tab 外；预览出线稿；交接可打开导演台。
- 最容易翻车：只删按钮却保留 `generateShotFrame` / `generateBatchTrials` / 预览彩色全出；或续写误覆盖旧集。
- 超预期机会：续写前显示将追加的集号范围；partial 失败可重试未完成集；交接页只留确认本集与打开导演台。

## 第一章：产品概述

NX9 编剧台续写与分镜台职责收口是一套 Desk UX 迭代，让短剧/漫剧创作者能够按明确集数生成与续写剧本、在分镜台用线稿确认构图，而无需在分镜台与导演台之间反复猜测「该在哪出彩图」。

### 1.1 差异化对比表

| 功能 | 通用编剧/分镜工具常见做法 | 本产品 | 实现方式 |
|---|---|---|---|
| 首次生成集数 | 一次生成固定长度或事后再拆集 | 生成前强制选 1 / 3 / 5 / 10 / 全部 | 生成前弹层写入 `targetEpisodeCount` |
| 续写控制 | 单集重生成或无集数语义 | 可选续写 N 集，从现有末集后续写 | 续写弹层 + 批量调用生成 skill |
| 线稿 vs 彩图 | 同一面板混出线稿与成图 | 分镜=线稿；导演=彩色关键帧 | UI 入口收口 + 文案/测试锁边界 |
| 模型选择位置 | 埋在预览大卡片内部设置 | 提到构图区 Tab 外，全局对本区生效 | 构图工具条右侧固定模型选择 |
| 3D 摆位入口 | 预览区旁路入口 | 分镜预览去掉 3D；3D 只在导演台 | 删除分镜预览 3D CTA |

说明：上表「通用工具」为品类归纳（基于公开信息的推断），不指向任何外部仓库或母版产品。

### 1.2 三类用户画像

**画像 A · 短剧编剧**
- 角色：负责大纲到分集成稿
- 核心目标：一次决定写几集，后续按集续写
- 对现有工具最大的不满：生成后不知道会出几集；续写只能「再点一次」无法控量
- 愿意切换的那一个功能：首次生成可选 1/3/5/10/全部，续写可选集数

**画像 B · 分镜师**
- 角色：把成稿拆成镜表并用线稿确认构图
- 核心目标：快速出线稿、拼故事板、交下游
- 对现有工具最大的不满：镜表/底部堆满线稿、试出、批出、3D，不知道主路径
- 愿意切换的那一个功能：镜表清爽、底部去噪、线稿路径明确

**画像 C · 导演/批图负责人**
- 角色：出彩色关键帧并审片
- 核心目标：拿到已确认构图的本集，批量出彩图
- 对现有工具最大的不满：分镜台已经试出一堆彩图，导演台又重出一遍
- 愿意切换的那一个功能：彩色关键帧唯一入口在导演台

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
|---|---|
| 编剧台首次生成集数选择与续写集数选择 | 自动根据字数智能推算最优集数（需额外产品研究，本轮不做） |
| 续写追加新集正文到 `ScreenplayPackage` | 跨项目续写、云端协作锁集（非本轮 Desk UX） |
| 分镜台 UI 收口：按钮删除/迁移、模型位置、预览卡片重构 | 重做导演台 3D/批出内核 |
| 强化「分镜线稿 / 导演彩图」职责与文案 | 禁止用户手动上传彩图到镜表（上传仍允许，仅生成职责收口） |
| 宫格线稿与批量线稿保留在构图能力区 | 新建第三种「半彩试出」生成模式 |

### 1.4 约束分层

| 硬约束（已拍板，不可违反） | 推荐默认 | 发挥空间 |

| 分镜预览去掉 3D 按钮与面板入口 | — | — |

#### b) 交互流程

```text
用户点击「生成剧本」
    |
    v
若已有进行中的生成 → Toast「生成进行中」并中止新开
    |
    v
打开集数选择弹层（默认 3）
    |
    +-- 取消 --> 关闭，不调用 skill
    |
    +-- 开始生成 --> 写入 generationPlan.targetEpisodeCount
            |
            v
         按集串行/分批调用 runGenerateScreenplaySkill
            |
            +-- 全部成功 --> 应用 patch，提示「已生成 N 集」，切到成稿 Tab
            |
            +-- 部分失败 --> 保留已成功集，提供「重试未完成」
            |
            +-- 全部失败 --> 状态 error，不清空已有旧成稿
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| idle | 无生成任务 | 生成按钮可点 | 打开弹层 |
| choosing | 弹层打开 | 遮罩 + 单选组 | 取消或开始 |
| generating | 已开始生成 | 进度条 + busy | 成功/失败/取消策略完成 |
| partial | 部分集成功 | 警告条列出未完成集 | 重试或保留 |
| success | 目标集全部落地 | Toast + 成稿列表有集 | 用户继续编辑 |
| error | 0 集成功 | 错误提示 | 关闭或重试 |

#### d) 依赖关系

- 读：`ScreenplayPackage.brief`、Agent 输入、现有 episodes（用于判断是否覆盖）
- 写：`screenplay.episodes[]`、`generationPlan`（见第五章）、节点 `status`
- 流：UI 弹层 → skill runner → package patch → Desk 成稿 Tab

#### e) 待决问题

1. 「全部」：Brief 有 `episodeCount` 则用之，否则上限 10（已拍板）。  
2. 已有成稿时再次生成：默认「仅追加新集」；弹层可提供「覆盖现有成稿」危险选项（P1，可不做）。

## 第四章：超越竞品的差异化功能

### 第 4.1 节 生成前强制集数契约

1. 竞品为何没有这个功能：许多工具把「写多长」交给模型自由发挥，产品侧缺少集数作为一等公民（基于公开信息的推断）。
2. 本产品如何实现：把 `targetEpisodeCount` 提升为生成前置必填，UI 与 package 双写，失败可按集重试。
3. 交互流程：见 3.1。
4. 风险与应对：模型不遵守集数 → 后置校验集数，不足则自动补生成一轮，超量则截断并提示。

### 第 4.2 节 线稿/彩图 Desk 级职责隔离

1. 竞品为何混在一起：单面板工具没有「分镜台/导演台」分工，只能把所有出图堆在一处（基于公开信息的推断）。
2. 本产品如何实现：NX9 已有三台主链；本轮用入口删除 + 文案 + 验收测试把边界钉死。
3. 交互流程：见 3.7。
4. 风险与应对：旧工作区仍残留试出图 → 允许展示历史图，但不再提供新的试出生成入口。

### 第 4.3 节 构图参数上提（模型在 Tab 外）

1. 竞品为何埋参数：设置常跟「大卡片」绑定，导致切换 Tab 后找不到模型（基于公开信息的推断）。
2. 本产品如何实现：模型选择成为构图区一等控件，对线稿预览与故事板相关出图统一生效。
3. 交互流程：见 3.4。
4. 风险与应对：与节点级 picture-gen 设置冲突 → 以 Desk 构图设置为准，并 sync 到执行节点。

    "version": 1,

    "composePreviewTitle": "线稿预览", // 展示名

## 第十一章：开发者交接说明

#### a) 实现顺序建议

严格按 **附录 C.2** 执行：先 F3/F7/F6（删入口）→ F5 模型上提 → F8 线稿路径 → F4 视觉 → F2/F1 编剧集数 → 改测试。

#### b) 最可能导致返工的三个决策

1. **续写是追加还是覆盖**  
   - 已拍板：始终追加到末尾，不覆盖旧集正文  
   - 转向信号：无（禁止改回覆盖）

2. **镜表是否保留线稿**  
   - 已拍板：保留线稿，只删试出  
   - 转向信号：无（本轮禁止再删线稿）

3. **预览是否仍可彩色全出**  
   - 已拍板：不可；必须改线稿路径  
   - 转向信号：无

#### d) 已知的未知项

1. 首次生成时，上游 `api.scriptScreenplay` 是否稳定返回目标集数：实现时应先写入 `brief.episodeCount`，生成后校验集数，不足则按集循环补齐（见附录 C）。  
2. 「全部」解析：Brief 无明确集数时上限 10，需在 UI 文案写清。  
3. 改线稿后旧工作区里已有的彩色试出图：允许继续展示历史 `imageUrl`，但禁止新的彩色生成入口。

#### e) 验收剧本

**验收剧本 1 · 首次生成 3 集**  
1. 打开空编剧台 → 点「生成剧本」→ 必须出现集数弹层。  
2. 选 3 → 开始 → 成稿出现 3 集（或 partial 可解释）。  
3. 不选集数无法开始生成。

**验收剧本 2 · 续写 2 集**

|                                          |
| 预览：当前共 3 集 → 将新增第 4–6 集        |
|                                          |
| 「取消」                    「开始续写」   |
+------------------------------------------+
`

样式：复用编剧台已有 sd2-btn / modal 或轻量绝对定位弹层即可，不必新设计系统。

#### 代码改法

**A. script-desk-runner.ts**

新增函数（名称可微调，语义必须是追加）：

`	ext
runAppendEpisodeSkill(pkg, options)
  options.nextEpisodeIndex: number   // 例如当前最大 index+1
  options.userInstruction?: string
返回：{ assistantText, patch } 其中 patch.screenplay.episodes = 旧集数组 + 新的一集
`

实现要点：

- 可复用现有 pi.scriptScreenplay + ingestTextToPackage(..., { episodeCount: 1 }) 得到一集。  
- 新集 index = options.nextEpisodeIndex，id 新建（不要复用旧 id）。  
- episodes = 旧 episodes.concat(新集)，**不要**用 map 替换。  
- prompt 里带上：Bible 摘要、前 1–2 集结尾摘要、请续写第 X 集，不要重复已有集。

保留旧的 
unGenerateScreenplaySkill(..., episodeIndex) 也可，但 UI 续写入口不要再走「替换」路径。

**B. ScriptDeskBlock.tsx**

- 增加 state：continueOpen、continueCount（默认 1）、continueBusy。  
- 「续写」按钮：onClick 打开弹层，而不是直接 handleRegenEpisode。  
- 「开始续写」：

`	ext
maxIndex = max(episodes.index)
for i in 0 .. continueCount-1:
  nextIndex = maxIndex + 1 + i
  result = await runAppendEpisodeSkill(currentPkg, { nextEpisodeIndex: nextIndex })
  currentPkg = touchScreenplayPackage(currentPkg, result.patch)
  savePkg(currentPkg)
  更新 tip / appendLog
`

- 失败：保留已成功追加的集；tip 说明失败于第几集；可提供「重试剩余」（P1）。
