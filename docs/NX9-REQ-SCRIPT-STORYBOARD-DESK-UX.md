# NX9 编剧台续写与分镜台职责收口 PRD

> 依据：`需求.txt`（2026-07-31）  
> 对齐：`docs/NX9-PROJECT-DEFECT-ANALYSIS.md` 主链「编剧台 → 分镜台 → 导演台」与 F-026 线稿/关键帧边界  
> 范围：编剧台加功能 2 项；分镜台修功能 6 项（含待分析决策）

## AI 速读卡

- 产品一句话：在 NX9 主链上补齐「按集数生成/续写剧本」，并收口分镜台只做线稿构图、导演台只做彩色关键帧批出。
- 核心循环：选题集数 → 生成/续写剧本 → 拆镜与线稿 → 确认本集 → 导演台批出彩色关键帧。
- 目标平台：NX9 Web 桌面端画布 Desk（编剧台 / 分镜台 / 导演台）。
- 硬约束：首次生成与续写必须可选集数；分镜台不得再作为彩色关键帧主入口；模型选择位于构图 Tab 外。
- 推荐默认：镜表去掉「试出」；「线稿」保留单镜入口但底部批量条删除、构图区保留批量/宫格；删分镜预览内 3D 按钮。
- 发挥空间：关键帧预览 Tab 卡片视觉、按钮分组、空态文案与微动效。
- P0 验收：首次生成可选 1/3/5/10/全部；续写可选续写集数；分镜底部四按钮消失；模型选择在 Tab 外；3D 按钮消失；彩色批出只在导演台。
- 最容易翻车：把「关键帧预览」继续做成彩色试出，导致与导演台职责再次重叠。
- 超预期机会：续写前显示「将从第 N 集接到第 M 集」预览；宫格线稿一键成为默认批量路径；交接页只留「确认本集 / 打开导演台」。

## 第一章：产品概述

NX9 编剧台续写与分镜台职责收口是一套 Desk UX 迭代，让短剧/漫剧创作者能够按明确集数生成与续写剧本、在分镜台用线稿确认构图，而无需在分镜台与导演台之间反复猜测「该在哪出彩图」。

### 1.1 差异化对比表

| 功能 | 通用编剧/分镜工具常见做法 | 本产品 | 实现方式 |
|---|---|---|---|
| 首次生成集数 | 一次生成固定长度或事后再拆集 | 生成前强制选 1 / 3 / 5 / 10 / 全部 | 生成前弹层写入 `targetEpisodeCount` |
| 续写控制 | 单集重生成或无集数语义 | 可选续写 N 集，从现有末集后续写 | 续写弹层 + 批量调用生成 skill |
| 线稿 vs 彩图 | 同一面板混出线稿与成图 | 分镜=线稿；导演=彩色关键帧 | UI 入口收口 + 文案/测试锁边界 |
| 模型选择位置 | 埋在预览大卡片内部设置 | 提到构图区 Tab 外，全局对本区生效 | 构图工具条右侧固定模型选择 |
| 3D 摆位入口 | 预览区旁路入口 | 分镜预览去掉 3D；3D 只在导演台 | 删除分镜预览 3D CTA |

说明：上表「通用工具」为品类归纳（基于公开信息的推断），不指向任何外部仓库或母版产品。

### 1.2 三类用户画像

**画像 A · 短剧编剧**
- 角色：负责大纲到分集成稿
- 核心目标：一次决定写几集，后续按集续写
- 对现有工具最大的不满：生成后不知道会出几集；续写只能「再点一次」无法控量
- 愿意切换的那一个功能：首次生成可选 1/3/5/10/全部，续写可选集数

**画像 B · 分镜师**
- 角色：把成稿拆成镜表并用线稿确认构图
- 核心目标：快速出线稿、拼故事板、交下游
- 对现有工具最大的不满：镜表/底部堆满线稿、试出、批出、3D，不知道主路径
- 愿意切换的那一个功能：镜表清爽、底部去噪、线稿路径明确

**画像 C · 导演/批图负责人**
- 角色：出彩色关键帧并审片
- 核心目标：拿到已确认构图的本集，批量出彩图
- 对现有工具最大的不满：分镜台已经试出一堆彩图，导演台又重出一遍
- 愿意切换的那一个功能：彩色关键帧唯一入口在导演台

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
|---|---|
| 编剧台首次生成集数选择与续写集数选择 | 自动根据字数智能推算最优集数（需额外产品研究，本轮不做） |
| 续写追加新集正文到 `ScreenplayPackage` | 跨项目续写、云端协作锁集（非本轮 Desk UX） |
| 分镜台 UI 收口：按钮删除/迁移、模型位置、预览卡片重构 | 重做导演台 3D/批出内核 |
| 强化「分镜线稿 / 导演彩图」职责与文案 | 禁止用户手动上传彩图到镜表（上传仍允许，仅生成职责收口） |
| 宫格线稿与批量线稿保留在构图能力区 | 新建第三种「半彩试出」生成模式 |

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
|---|---|---|
| 首次生成必须先选 1/3/5/10/全部，不可静默默认写死且不可感知 | 默认选中「3」集（短剧常见试写量） | 弹层视觉、选项说明文案 |
| 续写必须可选续写集数（≥1） | 默认续写 1 集；上限建议 10，超过需二次确认 | 续写预览文案、进度条样式 |
| 分镜台不再提供彩色关键帧/试出作为主路径 | 镜表去掉「试出」；底部去掉四按钮；3D 从分镜预览删除 | 按钮图标与分组 |
| 模型选择在构图 Tab 外，对本区生成生效 | 复用 `useConnectedPictureModels` | 控件宽度与折叠 |
| 彩色关键帧批出主入口仅导演台 | 「关键帧预览」Tab 改名为「线稿预览」或副文案标明只出线稿 | 预览网格密度、卡片样式 |
| 不破坏链 SSOT：`scriptBreakdown` / `chainStoryboard` / `storyboardPreview` 写回规则保持 | 批量能力迁到构图工具条，不删能力本身 | 空态与活动日志文案 |

### 第 3.1 节 编剧台 · 首次生成集数选择

#### a) ASCII 图

```text

+--------------------------------------+
| 生成剧本                              |

| 本次生成集数                          |
|  ( ) 1集   (•) 3集   ( ) 5集         |
|  ( ) 10集  ( ) 全部（按大纲写满）     |
|                                      |
| 「取消」              「开始生成」        |
+--------------------------------------+

进行中
+--------------------------------------+
| 正在生成 3 集…  第 2/3 集             |
| ████████░░░░ 67%                     |
| 「后台继续」（不可再开第二个生成任务）  |
+--------------------------------------+

失败
+--------------------------------------+
| 生成中断：上游 LLM 超时               |
| 已成功：第1集；未完成：第2–3集        |

```

#### b) 交互流程

```text
用户点击「生成剧本」
    |
    v
若已有进行中的生成 → Toast「生成进行中」并中止新开
    |
    v
打开集数选择弹层（默认 3）
    |
    +-- 取消 --> 关闭，不调用 skill
    |
    +-- 开始生成 --> 写入 generationPlan.targetEpisodeCount
            |
            v
         按集串行/分批调用 runGenerateScreenplaySkill
            |
            +-- 全部成功 --> 应用 patch，提示「已生成 N 集」，切到成稿 Tab
            |
            +-- 部分失败 --> 保留已成功集，提供「重试未完成」
            |
            +-- 全部失败 --> 状态 error，不清空已有旧成稿
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| idle | 无生成任务 | 生成按钮可点 | 打开弹层 |
| choosing | 弹层打开 | 遮罩 + 单选组 | 取消或开始 |
| generating | 已开始生成 | 进度条 + busy | 成功/失败/取消策略完成 |
| partial | 部分集成功 | 警告条列出未完成集 | 重试或保留 |
| success | 目标集全部落地 | Toast + 成稿列表有集 | 用户继续编辑 |
| error | 0 集成功 | 错误提示 | 关闭或重试 |

#### d) 依赖关系

- 读：`ScreenplayPackage.brief`、Agent 输入、现有 episodes（用于判断是否覆盖）
- 写：`screenplay.episodes[]`、`generationPlan`（见第五章）、节点 `status`
- 流：UI 弹层 → skill runner → package patch → Desk 成稿 Tab

#### e) 待决问题

1. 「全部」的语义：按 Brief 大纲集数写满，还是由模型自行决定集数？**推荐默认**：Brief 若含明确集数则用之，否则模型最多输出 10 集并在结果中标注实际集数。
2. 已有成稿时再次「生成剧本」：覆盖、追加、还是禁止？**推荐默认**：弹层增加「覆盖现有成稿 / 仅追加新集」；默认「仅追加」。

#### b) 交互流程

```text
用户点击某集旁「续写」或顶栏「续写」
    |
    v
弹出续写集数（默认 1）
    |
    +-- 取消 --> 关闭
    |
    +-- 开始续写 --> 计算 startIndex = max(episode.index)+1
            |
            v
```

相对现状：当前 `handleRegenEpisode` 是「按 episodeIndex 重生成/续写单集」，本模块升级为「可选 N 集批量续写」，并可从列表任意集触发（语义：从该集故事线向后追加，不覆盖该集正文，除非用户显式选「重写本集」——本轮不做重写，只做追加）。

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
|---|---|---|---|
| idle | 无续写 | 续写按钮可用 | 打开弹层 |
| choosing | 弹层开 | 集数控件 | 取消/开始 |
| continuing | 批量续写中 | 行内 spinner + 全局 busy | 完成/失败 |
| success | N 集写入 | Toast | 自动 |
| error | 本批 0 成功 | 错误 tip | 关闭 |

#### d) 依赖关系

- 读：现有 episodes、bible、brief
- 写：追加 episodes；若 `status===confirmed` 则按现规则 unconfirm
- 不写：分镜 `scriptBreakdown`（续写后需用户重新拆镜/增量拆镜，本轮只提示「成稿已变，请到分镜台同步」）

#### e) 待决问题

1. 从中间集点「续写」是「覆盖后续」还是「仅追加到末尾」？**推荐默认**：始终追加到末尾；按钮悬停提示写清「在全部集末尾追加 N 集」。
2. 自定义集数上限：建议 UI 上限 20；>10 二次确认。

#### e) 待决问题（需求分析结论）

**需求原文：去掉线稿与试出（不确定，待定，需要建议分析）**

| 选项 | 利 | 弊 | 结论 |
|---|---|---|---|
| A. 线稿+试出都删 | 镜表最干净 | 单镜返工必须去构图区，效率差 | 不推荐作默认 |
| B. 只删试出，保留线稿 | 对齐「分镜出线稿」；单镜可修 | 镜表仍有生成按钮 | **推荐默认** |
| C. 线稿+试出都保留 | 改动最小 | 与需求 6、F-026 冲突 | 否决 |

**产品决策：采用 B。** 试出从镜表删除；线稿保留。若后续用户反馈镜表仍吵，再用功能开关切到 A。

## 第四章：超越竞品的差异化功能

### 第 4.1 节 生成前强制集数契约

1. 竞品为何没有这个功能：许多工具把「写多长」交给模型自由发挥，产品侧缺少集数作为一等公民（基于公开信息的推断）。
2. 本产品如何实现：把 `targetEpisodeCount` 提升为生成前置必填，UI 与 package 双写，失败可按集重试。
3. 交互流程：见 3.1。
4. 风险与应对：模型不遵守集数 → 后置校验集数，不足则自动补生成一轮，超量则截断并提示。

### 第 4.2 节 线稿/彩图 Desk 级职责隔离

1. 竞品为何混在一起：单面板工具没有「分镜台/导演台」分工，只能把所有出图堆在一处（基于公开信息的推断）。
2. 本产品如何实现：NX9 已有三台主链；本轮用入口删除 + 文案 + 验收测试把边界钉死。
3. 交互流程：见 3.7。
4. 风险与应对：旧工作区仍残留试出图 → 允许展示历史图，但不再提供新的试出生成入口。

### 第 4.3 节 构图参数上提（模型在 Tab 外）

1. 竞品为何埋参数：设置常跟「大卡片」绑定，导致切换 Tab 后找不到模型（基于公开信息的推断）。
2. 本产品如何实现：模型选择成为构图区一等控件，对线稿预览与故事板相关出图统一生效。
3. 交互流程：见 3.4。
4. 风险与应对：与节点级 picture-gen 设置冲突 → 以 Desk 构图设置为准，并 sync 到执行节点。

```text
+--------------------------------------------------------------+
| UI 层：ScriptDeskBlock / use-storyboard-desk / PreviewWorkspace |
```

可替换技术原则：
- 推荐继续用现有 Desk + skill runner；若续写循环要抽 hook，可新建 `useEpisodeGenerationPlan`，但不可改 `ScreenplayPackage` 主字段语义。

## 第十一章：开发者交接说明

#### a) 实现顺序建议

1. 先做分镜职责收口（删试出/3D/底栏四按钮 + 模型上提）——改动面清晰，立刻降低用户困惑，并锁 F-026。  
2. 再改 `StoryboardPreviewWorkspace` 生成路径为线稿，避免「按钮没了但全出仍是彩图」。  
3. 最后做编剧台集数弹层与续写批量——依赖 skill 循环，需处理好 partial 失败。

#### b) 最可能导致返工的三个决策

1. **镜表是否保留线稿按钮**  
   - 安全默认：保留（决策 B）  
   - 转向信号：用户明确要求镜表零生成按钮，或数据证明 90%+ 线稿来自批量

2. **「关键帧预览」是否改名**  
   - 安全默认：改名为「线稿预览」  
   - 转向信号：大量老用户反馈找不到入口；若保留旧名必须加副标题硬说明

3. **「全部」集数语义**  
   - 安全默认：Brief 有集数用 Brief，否则上限 10  
   - 转向信号：用户 Brief 常写「12 集连载」却被截断——改为读取大纲集数或允许自定义

#### e) 验收剧本

**验收剧本 1 · 首次生成 3 集**  
1. 打开空编剧台 → 点「生成剧本」→ 必须出现集数弹层。  
2. 选 3 → 开始 → 成稿出现 3 集（或 partial 可解释）。  
3. 不选集数无法开始生成。

**验收剧本 2 · 续写 2 集**  
1. 已有 3 集 → 点续写 → 选 2。  
2. 结束后共 5 集，旧 3 集正文未被覆盖。  
3. 活动日志含续写集号范围。

**验收剧本 3 · 分镜底栏与试出消失**  
1. 打开分镜台镜表：无「试出」按钮；有「线稿」「编辑」（若采用默认 B）。  
2. 底栏无批量线稿/宫格/故事板/去导演台批出；可有「确认本集」。  
3. 构图 Tab 仍能批量线稿与宫格线稿。

**验收剧本 4 · 模型在 Tab 外、无 3D**  
1. 构图区在 Tab 按钮上方/外侧可见模型下拉。  
2. 线稿预览面板内无模型下拉、无 3D 按钮。  
3. 切换模型后出线稿使用新模型（网络面板或日志可观察）。

**验收剧本 5 · 彩图只在导演台**  
1. 分镜任意入口不能发起彩色试出/关键帧批出。  
2. 交接「打开导演台」可聚焦/打开导演台。  
3. 导演台仍有关键帧批出主按钮；相关 f026 扩展测全绿。
