## 1. 当前素材库总体评价

### 1.1 一句话定位（产品本质）

素材库**不是**文件管理器，而是：

> **AI 创作资产管理系统（SSOT）**：把「可重复注入生成的身份、造型、空间、物件、运镜语言、美学、声线」做成可建档、可锁定、可引用、可预检、可修复的生产资产。

用户把东西放进库，不是为了「存文件」，而是为了：

1. **一致性**：同一角色/服装/场景在多镜下不漂；  
2. **少抽卡**：锁定 Prompt + 参考图，减少每次手写；  
3. **可协作**：编剧草稿 → 库权威 → 分镜/生成消费同一套 ID/名；  
4. **可治理**：缺什么、坏什么、被谁用，可看见并可修。

### 1.2 现行成熟度（相对生产闭环）

| 层级 | 状态 | 说明 |
|------|------|------|
| 产品骨架 | **正确方向** | Bible 草稿 ≠ 库权威；`@类型:名` + 镜表绑定 + 设定就绪闸门，方向对 |
| 上镜实体（角/服/场/道） | **可用～半闭环** | 角色最强；服/场/道卡片壳已对齐；镜级换装/道具已有字段与 enrich |
| 语言词典（镜/风格） | **公共词典可用** | 镜头种子+层级筛选；风格轻量预设；**尚未与镜表/帧强绑 ID** |
| 声音 | **壳层刚重构** | 分型+卡片有；与角色参考音 / `voice.profiles` 三角仍糊 |
| 健康 / 影响 | **半诚实** | 多 Tab 真指标已有；影响分析可开抽屉但**缺一键重绑**；风格健康为空 |
| 版本 / 引用图 | **薄弱** | 无正式 AssetVersion；绑定仍大量靠「名」；生成侧不回写依赖账本 |
| 规模化 | **未准备** | 无虚拟列表/分页；批量除服装设定板外几乎没有 |

### 1.3 总体判断

**不要推倒重来。** 当前「实体库 + 词典库 + 声音库 + Modal SSOT」架构可继续承载生产。  
真正的结构性债是：**引用契约仍偏「按名字符串」**、**无版本语义**、**健康/影响止于展示**、**生成链路不回流依赖**、**文档声称「P0～P2 已收口」但验收口径仍有空洞**。

## 2. 当前素材库存在的核心问题

按「会不会直接拖慢出片 / 造成一致性事故」排序：

1. **绑定契约分裂**：镜表多用 `characterNames` / `sceneName`；库内有稳定 `id`；Mention 用「类型:名」。改名、重名、别名导致静默错绑或「失效引用虚高」。  
2. **无生产级版本**：锁只有 `locked` + 部分 `lockedPromptSnapshot`；改角色即全局漂移，无法「新版本 / 旧镜不跟」。  
3. **影响分析不可执行**：能看「谁上镜」，不能「选库重绑 / 仅本项目替换 / 断开引用」。  
4. **生成不记账**：出图/出视频不把「本镜用了哪些资产 ID」写回结构化依赖；健康「未使用」不可信于节点级。  
5. **服装/道具预检可信但未进 `ready`**：缺口展示了，硬闸门仍只卡角色/场景视觉——容易「绿灯进分镜、出图才崩」。  
6. **双编辑面**：制作台 AssetsHub 与完整 Modal 并存；虽已声明瘦客户端，仍有「改了 Prompt 以为设了妆」的认知风险。  
7. **词典与实体同壳不同契约**：镜头/风格当素材卡片很好，但消费端仍是本地枚举/`stylePreset` 字符串，库价值未吃满。  
8. **类型系统分裂**：`AssetRecord`（媒体文件）与创意资产（Character / Backlot / Sound / Style）两套，命名都叫「资产」，后续易混。  
9. **服装/场景/道具缺正式 `lockedPromptSnapshot` 字段**（健康靠类型断言），锁语义不完整。  
10. **规模与批量未设计**：百级尚可，千级会卡；无多选批量打标/锁定/导出。

## 3. 素材分类问题

### 3.1 现行分类（代码真值）

```
上镜实体：character / costume / scene / prop
语言词典：shot / style          ← 仅公共 scope
声音：    sound
兼容遗留：emotion / hook        ← 退出主导航
```

### 3.2 逐项裁决

| Kind | 应否存在 | 裁决 | 理由 |
|------|----------|------|------|
| 角色 | **必须** | **保留并加深** | 一致性核心；当前模型已接近生产级 |
| 服装 | **必须独立** | **保留** | ≠ 角色属性；需跨角色复用 + 镜级覆盖 |
| 场景 | **必须独立** | **保留**；变体作属性/子档，不拆库 | 空间一致性；天气/昼夜是变体不是新 kind |
| 道具 | **必须独立** | **保留** | 已建库；禁止退回场景字符串 |
| 镜头 | **应存在，但是词典** | **保留公共词典**；勿当实体 | Prompt/运镜模板，不是「一张图资产」 |
| 风格 | **应存在，但是预设** | **保留公共轻量预设** | 名+Prompt+可选参考；服务 `stylePreset` |
| 声音 | **必须** | **保留并拆消费语义** | 配音/SFX/BGM 同 Tab 分型即可，勿再拆三个顶栏 Tab |
| 情绪 | **不应独立日常库** | **保持降级** | → 镜头 `emotionTags` + 角色表情格 |
| 爆点/钩子 | **不应在素材库** | **保持退出** | SSOT=`brief.hooks` |
| 灯光/时代/世界观 | **否** | **不做独立库** | 场景字段 / 项目设定 |
| 载具 | **否** | **道具子类** | `category`/`tags` |
| 表情库 | **否** | **不做** | 与角色格抢职责 |

### 3.3 类型间关系（正确模型）

```
角色 ──默认──► 服装
  │              ▲
  │              │ 镜级 costumeOverrides
分镜 ───────────┘
  ├── sceneName / sceneAssetId ──► 场景 ──propIds──► 道具
  ├── propIds ──► 道具（本镜关键）
  ├── @镜头 / cameraMove ──► 镜头词典（弱绑→应进化为可选 shotAssetId）
  ├── stylePreset ──► 风格预设（弱绑→应进化为可选 styleAssetId）
  └── 配音 ──► 角色.referenceAudio 或 声音库(voice)
```

### 3.4 每类资产「真正有价值」的数据（目标最小集）

| 维度 | 角色 | 服装 | 场景 | 道具 | 镜头 | 风格 | 声音 |
|------|------|------|------|------|------|------|------|
| 身份名+稳定 id | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 生产 Prompt + Negative | ✓ | ✓ | ✓ | ✓ | Prompt | Prompt | Prompt/描述 |
| 主媒体 | 定妆/三视图/设定板 | 设定板/正面衣 | 主景/多参考 | 主参考/三视 | GIF/例图可选 | 参考图可选 | 音频可选 |
| 锁定 | ✓ | ✓ | ✓ | ✓ | 可选 | 可选 | 可选 |
| 关联 | costumeId | 被角色用 | propIds | linkedSceneIds | lexicon 分类 | family | soundKind；可挂角色 |
| 版本 | **缺** | **缺** | **缺** | **缺** | 低优先 | 低优先 | 低优先 |
| 使用账本 | **半有（按名）** | **弱** | **半有** | **弱（场景挂接）** | 几乎无 | 几乎无 | 几乎无 |

**结论**：不是「只有一张图+名字」——角色/服装已远超；但**消费与账本层仍像轻量标签系统**。

## 4. 数据模型问题

### 4.1 现状映射

| 概念 | 当前对应 | 缺口 |
|------|----------|------|
| Asset（创意） | `CharacterProfile` / `BacklotWorkspaceItem` / `Sound*` / `Style*` | 无统一基类；靠 `AssetLibraryItem` 投影 |
| AssetType | `AssetLibraryKind` | 合理 |
| AssetVersion | **无** | 仅软删 + 锁快照（不全） |
| AssetReference | `AssetRef` + Mention 字符串 | 与镜表名并行，未统一 |
| AssetRelation | 零散字段（costumeId、propIds、overrides） | 无双向查询 API |
| AssetUsage | 健康分析临时 Map | 不持久、不覆盖节点 |
| AssetTag | `tags[]` | 无受控词表 |
| AssetPrompt | creative.prompts / consistencyPrompt | 不齐；锁快照字段不全 |
| AssetGeneration | 无独立表；写回 URL | 无「哪次生成用了哪些资产」 |
| AssetBinding | 镜表 names/ids 混用 | 改名脆弱 |
| ProjectAsset | workspace document | 有 |
| GlobalAsset | `PublicLibraryPayload` | 有；内置只读+导入副本已部分落地 |
| Media Asset | `AssetRecord`（picture/video/…） | **另一套**，易与创意库混淆 |

### 4.2 「一个角色到底是什么」——目标（在现有 `CharacterProfile` 上加深，不换皮）

保留并强化现有结构：

```
CharacterProfile
├── id / name / aliases / tags
├── bible（叙事层）
├── consistencyPrompt + creative.consistency（锁/negative/快照）
├── 多视图 URL + fullSheet
├── 变体格（表情/姿态/…）
├── costumeId（默认服装）
├── referenceAudioUrl
└── 【待加】version / publishedAt / usageIndex（可选派生）
```

**不要**再发明平行的「角色图片对象」顶层类型；图片是角色的媒体槽位。

### 4.3 关键模型债（必须写进问题表）

- **DM-01** 无 AssetVersion → 改即全局漂。  
- **DM-02** 镜表绑定名优先 → 改名/重名事故。  
- **DM-03** 服/场/道 `lockedPromptSnapshot` 未入正式类型。  
- **DM-04** `style: []` 健康空白；风格无 lock 语义。  
- **DM-05** `AssetRecord.refCount` 与创意库使用量不通。  
- **DM-06** 场景 `props: string[]` 与 `propIds` 双轨仍可并存污染。  
- **DM-07** 公共内置覆盖策略（同名用户条覆盖内置）需产品确认，防「静默污染观感」。

## 10. 素材生命周期问题

```
创建 → 上传/AI生成 → 编辑 → 锁定 → 被引用 → 修改 → ?版本 → 替换 → 软删 → 恢复
```

| 阶段 | 现状 | 缺口 |
|------|------|------|
| 草稿 | 无显式 draft 状态 | 可用「未锁定」近似，不必新状态机（P3） |
| 生成中 | 依赖画布任务 | 库内进度弱 |
| 失败 | toast/日志 | 无资产级 failed 标记 |
| 已确认 | `locked` | 服/场/道锁快照字段不全 |
| 废弃 | `deletedAt` 软删 | 有回收站 |
| 版本 | **无** | P1 核心 |
| 回滚 | **无** | 随版本 |
| 复制 | 公共→私有 / 内置导入副本 | 有 |
| 替换 | 改 URL 原地替换 | 历史镜跟着变（无 pin version） |
| 删除 | 软删；引用仍按名可能「幽灵可用」或「失效」 | 删除前应扫引用 |
| 修改已引用 | 立即生效 | **危险默认**；应提示影响并可选新版本 |

## 11. 素材引用关系问题

### 11.1 现状

- **正向（位置→素材）**：镜表 names/ids、overrides、propIds、@Mention、节点 AssetRef、角色 costumeId、场景 propIds。  
- **反向（素材→位置）**：健康分析临时计算角色/场景上镜；服装绑角色；**无持久 usage index**。

### 11.2 目标契约（最小可执行）

1. **稳定 id 优先，名作展示与兼容键**；别名参与解析但不作唯一主键。  
2. 每个可生产资产可查询：`usedBy: { storyboardShots[], nodeRefs[], characterBindings[] }`。  
3. 修改策略三选一（UI 明示）：  
   - **就地更新**（当前默认）  
   - **另存新版本**（旧引用钉旧版）——P1  
   - **仅复制到项目再改**（公共不污染）——已有路径，需强化  
4. 删除：引用数>0 → 强制「替换或断开」；禁止静默软删后假装健康。

### 11.3 立即要做 vs 不要做

| 做 | 不做（现阶段） |
|----|----------------|
| 失效引用：列表 + **从库选目标重写镜表名/Id** | 完整知识图谱可视化 |
| 删除前引用计数提示 | 全局替换跨项目 |
| 使用次数上卡（角色/场景先） | 实时协同编辑锁 |

## 29. 核心用户流程

1. **建角色**：新建 → 上传/生成定妆或设定板 → 补 Prompt → 锁 → 分镜按库选择绑定（写 id+名）。  
2. **替换角色**：影响分析 → 看 N 镜 → 确认范围 → 重绑或新版本。  
3. **@引用**：分镜/@条选库 → 插入 `@类型:名` → enrich。  
4. **出图记账**：executor 写 `usedAssetIds`（角/服/场/道/风格）。  
5. **出视频记账**：同 4，另记镜头词典 id（若有）。  
6. **改角色**：弹「就地 / 新版本」；旧镜 pin 旧 revision。  
7. **删除**：引用>0 → 替换或断开 → 软删。  
8. **公共→项目**：复制/导入副本 → 只改私有。

## 34. 最终验收标准

生产可用的素材库必须同时满足：

1. **建得全**：角/服/场/道/声可建；镜/风公共可维；内置只读可复制。  
2. **引得稳**：id 优先；@ 可 enrich；镜级服/道生效。  
3. **检得真**：健康非假零；未使用/失效定义与实现一致。  
4. **修得了**：失效引用可在库内重绑；删除有引用拦截。  
5. **闸得清**：设定就绪区分硬缺（角/场视觉）与警告（服/道）。  
6. **不污染**：改项目副本不影响公共/内置。  
7. **可追溯（P1）**：出图记录 usedAssetIds；角色可 revision。  
8. **无假按钮**：影响分析、健康 chip、导入副本均有真实结果。  
9. **规模（P2）**：≥500 实体卡片可滚动不冻。  
10. **不做清单被遵守**：情绪/爆点不回顶栏；无团队库/LoRA 库。
